# CS320-Software-Test-Automation-QA
I can ensure that my code is functional by comparing it directly to the software requirements and creating tests for both valid and invalid conditions. In Project One, I used JUnit tests to verify the contact service requirements. I tested valid contact creation, field length limits, null values, phone number formatting, duplicate IDs, updates, and deletion. I also used assertions to confirm that the program returned the expected results and threw exceptions when invalid data was provided. To improve security, I can validate all inputs, restrict changes to fields that should not be updated, and avoid trusting data without checking it first. Regular testing and code reviews can also help identify defects before the software is released.

I interpret user needs by breaking each requirement into specific behaviors that the program must support. For example, the contact requirements stated that every contact needed a unique ID that could not be longer than ten characters or updated after creation. I translated that requirement into validation within the Contact class and tests that checked valid IDs, null IDs, IDs that were too long, and duplicate IDs. This process helped me see how written requirements can become program logic and test cases. If a requirement is unclear, I would ask questions and confirm the expected result before implementing it.

I approach software design by first identifying the responsibilities of each class and separating the data from the operations performed on it. In the contact service, the Contact class stored and validated contact information, while the ContactService class managed adding, updating, and deleting contacts. I then designed tests around each requirement and considered normal cases, boundary values, and invalid input. This approach keeps the code organized and makes defects easier to locate. In future projects, I plan to continue designing software in smaller components, connecting each component to a requirement, and testing throughout development instead of waiting until the program is complete.
